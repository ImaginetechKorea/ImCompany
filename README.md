# ImCompany — 소규모사업자 수주·매출 관리

Windows PC 1대에서 사용하는 한국어 로컬 업무 프로그램입니다. .NET 10 / ASP.NET Core / EF Core / SQLite로 구현했습니다. 운영 자료는 처음 실행할 때 빈 상태로 시작합니다.

## 실행

1. `Start-ImCompany.cmd`를 더블 클릭합니다. 배포 파일이 있으면 `publish/ImCompany.exe`를 실행합니다.
2. 브라우저에서 `http://127.0.0.1:5274`가 열립니다.
3. 설정에서 회사 정보와 기본 VAT 정책을 입력합니다.

`publish` 폴더를 다른 Windows x64 PC로 복사해서 사용할 수 있습니다. **ImCompany.exe와 wwwroot 폴더를 함께 보관하세요.** 배포본에는 .NET 런타임이 포함되어 있습니다.

데이터 기본 위치는 `%LOCALAPPDATA%\ImCompany\ImOrder`입니다. 실행 파일 교체와 데이터 저장을 분리했습니다. 저장 위치를 바꾸려면 `ImCompany.exe --data-root "D:\업무자료\ImCompany"`로 실행합니다. 포트 변경은 `--port 5276`입니다. 기존 버전과의 호환을 위해 데이터 폴더의 마지막 이름은 ImOrder로 유지합니다. 한 데이터 폴더는 동시에 한 프로그램만 사용합니다. 브라우저 창을 닫아도 서버는 실행 중이며, 설정의 **프로그램 종료**로 종료합니다.

거래처 등록 또는 수정에서 **주거래처로 지정**을 체크하면 거래처 검색과 선택 목록의 앞에 표시됩니다.

## 첫 거래 처리

1. **거래처**에서 상호와 연락처를 등록합니다. 거래가 있는 거래처는 ‘사용 안 함’으로 보존합니다.
2. **수주 관리**에서 프로젝트와 품목·수량·단가를 입력하고 저장합니다.
3. **발주 관리**에서 공급처 발주와 입고·매입·지급을 관리합니다.
4. 수주 상세에서 납기·고객 발주번호·지급 조건을 설정하고, 납품·설치·개발·시운전·검수·준공 기록을 남깁니다.
5. 수주에서 계약금·중도금·잔금 청구 내용을 확인하고 저장하면 청구와 미수금에 바로 반영됩니다. 기존 청구 초안은 별도로 확정해야 반영됩니다.
6. **입금 관리**에서 프로젝트, 실제 입금일과 금액을 입력하고 저장하면 프로젝트 잔금에 바로 반영됩니다. 청구 전 선입금도 입력할 수 있습니다. 이전에 등록한 미연결 입금은 기존 연결 화면으로 처리합니다.

프로젝트에 직접 등록한 입금은 개별 청구에 임의로 나누지 않습니다. 이 경우 개별 청구의 미수금·기한 경과 대신 프로젝트별 잔금을 확인하세요.

## 금액과 문서

- 프로젝트 청구 미수금 = 확정 청구 합계 − 프로젝트 입금 합계 (최저 0원).
- 미청구 잔액 = 수주 계약 합계 − 확정 청구.
- 전체 잔금 = 계약 합계 − 프로젝트 입금 합계. 선입금이 있으면 청구 미수금과 미청구 잔액의 합계가 전체 잔금과 다를 수 있습니다.
- 미배분 입금은 거래처 잔액으로 별도 표시하며 수주 입금으로 계산하지 않습니다.
- C# decimal로 계산하고 원 단위 Int64로 저장합니다. 수량·단가·할인은 소수점 네 자리까지 지원합니다.
- VAT 별도/포함, 과세/면세/영세율, 품목/문서 단위, 버림/반올림을 지원합니다. 잔금 청구는 공급가액·VAT 잔액을 각각 사용합니다.
- 문서 승인·수주 전환 시 거래처와 품목·계산 정책을 보존합니다. 설정 변경으로 기존 계약을 재계산하지 않습니다.
- **계약 변경**은 전체 계약 품목과 사유를 기록하며 확정 청구보다 계약을 줄일 수 없습니다.
- **수주 종료**는 전체 미수금과 미청구 금액이 모두 0원이면 자동으로 처리됩니다. 기존에 조건을 충족한 수주는 상세 화면에서 직접 종료할 수 있습니다. 납품·작업 등록은 필수가 아니며, 종료 후 수정을 하려면 사유를 남기고 수주를 재개합니다.
- 문서 상세의 **인쇄 / PDF**에서 브라우저 인쇄의 ‘PDF로 저장’을 선택합니다. 목록의 **엑셀** 버튼은 XLSX 파일을 내려받습니다.
- 세금계산서는 외부 발급일·승인번호를 기록합니다. 실제 전자세금계산서 발급 기능은 없습니다.

## 첨부·백업·복원

문서 상세의 **첨부파일**에서 PDF, XLSX, DOCX, PNG, JPG, TXT를 첨부합니다. 기본 최대 크기는 50MB입니다. 형식과 파일 서명을 검사하고 UUID 이름 및 SHA-256을 저장합니다. 삭제는 목록에서 숨기는 논리 삭제입니다.

**설정 → 엑셀 백업 만들기**에서 거래처·수주·작업·청구·입금·발주·입고·매입·지급 내역을 시트별로 볼 수 있는 엑셀 파일을 만듭니다. 파일 안에는 데이터베이스, 회사 설정, 첨부 원본 및 무결성 검사용 복원 정보도 들어 있습니다. 실행 중 하루 한 번 자동 저장하며 백업 목록의 파일명으로 내려받을 수 있습니다. 중요한 백업은 다른 저장장치에도 보관하세요.

백업 목록에서 **복원**을 선택하고 ‘복원’을 입력합니다. 현재 자료도 엑셀로 백업하고 파일 해시·DB 무결성·첨부를 검증한 뒤 교체합니다. 엑셀에서 백업 원본을 편집하여 저장하면 복원 정보가 손상되거나 제거될 수 있으므로, 내용을 수정할 때는 복사본을 사용하세요. API 키와 MCP 토큰은 보안상 백업에 포함하지 않습니다.

## ChatGPT 대화 패널과 업무 자동 입력

화면 오른쪽 **AI 업무 도우미**에서 업무를 요청합니다. 작은 화면에서는 상단 **AI 도우미** 버튼으로 엽니다.

1. 이미지(PNG/JPG), PDF 또는 TXT 파일을 첨부하거나 대화 입력창에 복사한 이미지와 텍스트를 붙여 넣습니다. 이미지와 PDF는 파일당 10MB, TXT는 1MB까지 지원합니다. PDF는 파일당 5페이지, 대화당 최대 10페이지이며 한 번에 최대 3개 파일을 첨부합니다. 직접 입력한 텍스트는 5만 자 이하여야 합니다.
2. 예를 들어 ‘첨부한 자료를 읽고 거래처와 발주를 등록해 줘’ 또는 ‘이 내용으로 수주와 입금을 등록해 줘’라고 요청한 뒤 **ChatGPT로 보내기**를 누릅니다. 보내기 전까지 파일과 텍스트는 외부에 전송하지 않습니다.
3. AI가 거래처, 수주, 납품·작업·검수, 청구, 입금, 발주, 입고, 매입, 지급의 입력안을 각각 제안합니다. 입력안의 **입력 내용 확인 · 저장**에서 거래처와 수주, 품목, 금액, 날짜를 확인하고 수정합니다. 거래처는 별도 확인 카드에서 저장합니다.
4. **확인하고 저장**을 누르면 해당 업무가 등록됩니다. 선택한 원본 파일은 저장된 업무의 첨부파일에 함께 보관할 수 있습니다. 작업의 원본은 작업 목록의 **첨부**에서 볼 수 있습니다. 청구는 확인 후 저장하면 바로 반영됩니다. 입금은 프로젝트를 확인하고 저장하면 잔금에 바로 반영됩니다.

파일에서 읽지 못한 항목이나 연결할 거래처·수주가 불분명한 경우 직접 선택하거나 입력해야 합니다. 금액은 서버에서 다시 계산합니다. 문서의 내용이 자동으로 저장을 승인하지는 않습니다. **＋ 새 대화**로 다른 자료를 처리할 수 있으며 Ctrl+Enter로 메시지를 보낼 수 있습니다.

대화·미등록 제안·분석용 파일은 24시간 동안 로컬 임시 자료로 유지하며 앱 시작 시 만료 자료를 정리합니다. 저장한 업무와 원본 첨부는 일반 자료로 계속 보관합니다.

**설정 → AI 연결 → ChatGPT 로그인 (Codex)**는 PC에 설치된 Codex의 기존 ChatGPT 로그인을 사용합니다. 이 PC에서 실제 연결과 이미지·스캔 PDF 분석을 검증했습니다. 별도 API 키는 필요하지 않으며 ChatGPT 계정의 Codex 사용 한도가 적용됩니다. 다른 PC에서는 Codex를 설치하고 ChatGPT 로그인을 완료해야 합니다. 모델 칸을 비우면 Codex 기본 모델을 사용합니다.

**AI API 키 사용**을 선택하면 이미지 입력과 JSON Schema 응답을 지원하는 Chat Completions 호환 HTTPS 주소·모델·API 키를 직접 설정할 수 있습니다. 키는 Windows DPAPI로 보호합니다. API 제공자별 실제 연결은 별도 확인이 필요합니다.

AI는 업무 요청을 구조화해서 제안하고, 프로그램이 허용된 도구와 입력을 검사해 실행합니다. 모델에는 명령 실행·웹 브라우저·파일 수정·외부 앱 도구를 제공하지 않습니다. 파일에 적힌 문장으로 승인 규칙이나 권한을 바꿀 수 없습니다. 주민등록번호 등 불필요한 개인 식별정보를 거래처 필드로 추출하도록 요청하지 않습니다.

거래처를 비롯한 모든 업무 입력안은 사용자가 검토한 뒤 저장합니다. 청구와 입금은 사용자가 확인한 뒤 저장하며, 취소와 복원은 AI가 직접 처리하지 않습니다.

MCP는 공식 C# SDK 기반 로컬 Streamable HTTP 서버입니다. **설정 → MCP 활성화 → 주소·토큰 보기**에서 Bearer 인증 연결 정보를 확인합니다. 도구는 거래처·수주·청구 검색/조회, 잔액 조회, 청구 입력안 작성, 입금 배분 후보 제안입니다. 외부 PC 접속은 지원하지 않습니다.

연결 구현은 [OpenAI 공식 Codex 문서](https://learn.chatgpt.com/docs/non-interactive-mode)의 비대화형 실행 및 구조화 응답 방식을 사용합니다.

## 빌드와 검증

소스 실행에는 .NET SDK 10.0.401이 필요합니다. 패키지 버전은 프로젝트와 `packages.lock.json`에 고정했습니다.

```powershell
dotnet restore
dotnet build --no-restore
.\Publish-ImCompany.ps1
```

자동 검증에는 Node.js도 필요합니다. AI 검증 스크립트 tests/ai-integration.mjs는 ChatGPT 로그인이 된 테스트 서버에서 별도로 실행합니다. 다른 테스트 서버가 실행 중이지 않은 상태에서 실행하세요.

```powershell
.\tests\Run-Tests.ps1
```

테스트는 `data/test-<고유값>`을 사용하고 운영 자료를 변경하지 않습니다. 결과는 `tests/results/integration.json`에 저장됩니다. 테스트의 업무일은 사양서 기준 2026-10-31입니다.

## 구현 범위와 남은 검증

이 버전은 핵심 업무와 데이터 보호 기능을 연결한 초기 구현입니다. 사양서 전체의 최종 인수 완료를 의미하지 않습니다.

- 54개 자동 검증을 통과했습니다. 포함/면세/VAT 반올림, 계약 잔액, 초과·중복·동시 요청, 스냅샷, 첨부, 백업 복원, 손상 백업 거절, MCP 인증·조회·초안 권한을 검사했습니다.
- ChatGPT 로그인으로 실제 이미지·스캔 PDF 분석과 거래처 검토·저장 등 AI 검증 27개를 추가 통과했습니다. 기존 업무 회귀 검증은 54개입니다. 다른 API 제공자, Claude 등 외부 GUI MCP 클라이언트, 여러 프린터의 장문 한글 출력은 별도 확인이 필요합니다.
- PDF는 브라우저의 인쇄/PDF 저장을 사용합니다. 서버에서 PDF 파일을 직접 생성하는 기능은 없습니다.
- DB는 EF Core 스키마 초기화와 `SchemaVersions` v1을 사용합니다. 후속 스키마 변경에는 명시적인 마이그레이션을 추가해야 합니다.
- 사용자 지정 PDF 서식 편집, 거래처 물리 삭제, 음수 전표·환불, 은행 연동, 전자세금계산서 실제 발급, 다중 사용자·원격 접속은 제공하지 않습니다.




## 도움말과 세금계산서 입력

프로그램 왼쪽 메뉴의 **도움말**에서 처음 시작하기, 거래처·수주·발주·납품, 청구·입금·미수금, AI 사용, 백업과 문제 해결 방법을 확인할 수 있습니다.

**청구 관리 → 세금계산서로 입력**에서 매출 세금계산서 이미지 또는 PDF를 선택하고 AI에 보내면 청구 입력안을 만듭니다. 우리 회사가 공급자인지, 거래처·수주·금액·발급 정보와 지급기한을 확인한 다음 초안을 저장하고 별도로 확정합니다. 실제 전자세금계산서 발급 기능은 아닙니다. 같은 승인번호의 중복 등록과 확인 가능한 사업자번호 및 세액 불일치를 검사합니다.

AI 패널의 **입력 지우기**는 보내기 전 입력한 글과 첨부 대기 파일만 지우며 이전 대화는 유지합니다.

청구의 지급기한은 선택 입력입니다. 입력한 경우 청구일 이후여야 하며, 미지정 청구도 미수금에 포함되지만 기한 경과로 표시되지 않습니다.

## 발주 · 입고 · 매입 · 지급

왼쪽 **발주 관리**에서 기존 거래처를 공급처로 선택하고 발주서의 품목·수량·단가를 입력합니다. 수주 프로젝트를 선택적으로 연결할 수 있으며, 발주 상세에서 인쇄 또는 PDF로 저장할 수 있습니다. 저장해도 공급처에 자동 전송되지 않습니다.

발주 상세에서 품목별 입고 수량을 여러 번 나누어 기록하고, 매입 증빙의 공급가액과 부가세 및 실제 지급 내역을 등록합니다. 발주 잔금은 발주금액에서 지급 합계를 뺀 금액이고, 매입 기준 미지급금은 매입 합계에서 지급 합계를 뺀 금액(최저 0원)입니다. 지급 전 등록된 금액은 선지급으로 표시됩니다. 은행 이체는 실행하지 않습니다.

잘못 입력한 입고·매입·지급은 취소 사유를 남긴 뒤 다시 등록합니다. 연결된 내역이 있는 발주를 수정하거나 취소하려면 먼저 관련 내역을 취소해야 합니다. 첨부파일은 발주 상세에서 보관하며 엑셀 백업에도 발주·입고·매입·지급 시트와 원본 복원 데이터가 포함됩니다.
